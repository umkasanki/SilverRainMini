# Silver Rain Mini — план разработки

Мини-приёмник радио «Серебряный Дождь» для macOS: значок в панели меню,
стеклянная панель управления в стиле Пункта управления macOS 26, воспроизведение
потока на Mac и вывод на колонки по AirPlay.

Аналог виндового приложения **Silver Rain Radio**
(`C:\Program Files (x86)\Silver\Radio.exe`).

Этот файл объясняет, *почему* решения такие. Что именно делает версия 1.0 и как это
проверяется — в техническом задании [SPEC.md](SPEC.md).

---

## 1. Цели и границы

### Цель
Лёгкое нативное приложение без значка в Доке, которое живёт в верхней панели меню
и в один клик включает живой эфир «Серебряного Дождя».

### Почему не большое приложение
На Mac уже стоит «Радио Серебряный Дождь» из App Store (RADIO SILVER RAIN LTD).
Это iPad-версия, Apple помечает её как «Не проверялось для macOS». Она открывается
обычным окном, в панели меню не живёт и в автозагрузку не годится.
Silver Rain Mini его не заменяет, а дополняет: «включил и забыл».

### Не делаем
- запись эфира, архив передач, подкасты;
- будильник (он уже есть на Sonos);
- публикацию в App Store и нотаризацию;
- поддержку macOS ниже 26.

### По чьим правилам

Код, интерфейс, тексты и документация следуют официальным правилам Apple, а не
нашим привычкам и не тому, «как принято» в вебе.

| что | документ |
|---|---|
| интерфейс | **Human Interface Guidelines**, раздел macOS — <https://developer.apple.com/design/human-interface-guidelines/> |
| именование и структура кода | **Swift API Design Guidelines** — <https://swift.org/documentation/api-design-guidelines/> |
| доступность | раздел **Accessibility** в HIG |
| слова в интерфейсе | словарь самой macOS: берём системную формулировку («Настройки…», «Выйти», «Звук»), а не придумываем свою |

На практике это значит, в порядке убывания частоты обращения:

- **Интерфейс приложения неотличим от системного.** Панель собрана из системных
  материалов и системных цветов, а не из своих красок (6.2); окно настроек выглядит
  как Системные настройки macOS, а не как своя форма (6.3).
- Значки — из **SF Symbols**, а не перерисованные.
- Стандартные API там, где они есть: `Settings`, `Form`, `SMAppService`,
  `MPNowPlayingInfoCenter` — без самодельных замен. `MenuBarExtra` сюда не попал
  по причине, записанной в 7.
- **Код структурирован** по раскладке из раздела 7: один файл — одна
  ответственность, имена по Swift API Design Guidelines, никаких «утилит на всё».
- Метки доступности на каждом управляющем элементе, работа с клавиатуры,
  разумные размеры мишеней.

**Правило разрешения споров.** Если наше решение расходится с правилами Apple,
расхождение пишется в журнал решений вместе с причиной. Молча — нельзя: иначе
через месяц его либо «починят» обратно, не зная причины, либо повторят там, где
причины нет.

Пять расхождений уже есть, все записаны: толстый ползунок громкости (6.2),
настройки с выходом под правым кликом (6.6), `NSStatusItem` вместо
`MenuBarExtra` (7) — прямое следствие предыдущего, — устаревающий
`activate(ignoringOtherApps:)` для окна настроек и сегментный переключатель вместо
панели вкладок в окне настроек (оба — журнал, 17.10.2026).

## 3. Потоки

Проверены 16.10.2026: HTTP-заголовки, 10-секундные записи, `ffprobe`.

### Рабочие

| # | Адрес | Кодек | Реальный битрейт | Где используется |
|---|---|---|---|---|
| 1 | `https://silverrain.hostingradio.ru/silver64.aac` | HE-AAC, 44,1 кГц, стерео | **96 kbps** (в имени «64») | будильник и ярлык Sonos (`silver-sonos.vbs`) |
| 2 | `https://silverrain.hostingradio.ru/silver128.mp3` | MP3, 44,1 кГц, стерео | 128 kbps | виндовый Radio.exe (через `silver.ru/radio/48.m3u`) |
| 3 | `https://silverrain.hostingradio.ru/silver48.aac` | HE-AACv2, 44,1 кГц, стерео | 48 kbps | — |

- Все три работают и по `http://`, и по `https://`. В приложении только HTTPS:
  исключения App Transport Security не нужны.
- **По умолчанию поток № 1.** Это лучшее качество: AAC современнее, у MP3 128
  частоты срезаны примерно на 16 кГц.
- Поток № 3 — запасной для слабой сети.
- В потоках есть ICY-метаданные (`icy-metaint: 16000`), но при проверке
  `StreamTitle` был пустым. Нужно проверить ещё несколько раз в разное время (этап 3).

### Сравнение качества

Замер 17.10.2026: все три потока записаны **одновременно** по 20 с, сравнивается
один и тот же фрагмент эфира. Уровень сигнала выше заданной частоты и уровень
боковой составляющей стерео (L−R):

| Поток | > 16 кГц | > 18 кГц | > 19 кГц | стерео L−R |
|---|---|---|---|---|
| AAC 96 (`silver64.aac`) | −54 дБ | −60 дБ | −65 дБ | −19,2 дБ |
| MP3 128 (`silver128.mp3`) | −60 дБ | −77 дБ | **−90 дБ** | −19,7 дБ |
| AAC 48 (`silver48.aac`) | −55 дБ | −61 дБ | −66 дБ | **−21,3 дБ** |

- **AAC 96 — лучший из доступных:** верх до 19 кГц, стерео полное. Поэтому он по умолчанию.
- **MP3 128** честно кодирует до 16 кГц, выше срезан. Звучит глуше, но это другой
  кодек — запасной, если AAC где-то капризничает.
- **AAC 48** (HE-AACv2) держит верх, но стерео у него параметрическое: из моно
  с подсказками, сцена уже. Только для слабой сети.
- Оговорка: в HE-AAC всё выше примерно 11 кГц не закодировано, а восстановлено
  декодером по подсказкам (SBR). «Есть верх» не значит «точный верх»; на слух это
  воздух и прозрачность, и для эфира это лучший из трёх вариантов.

### Полнота списка

Других московских потоков у станции нет — проверено 17.10.2026 тремя путями:
- новое официальное приложение «Серебряный Дождь» 2.0.0 (`ru.silver.radio.app`)
  берёт эфир из `https://silver.ru/radio/regions.json`; для Москвы там
  `silver128.mp3` и `silver48.aac` — оба у нас есть. `silver64.aac` есть только у нас;
- виндовый `Radio.exe` знает только `silver128.mp3` (через `48.m3u`);
- на `silverrain.hostingradio.ru` перебраны ещё 26 имён (192/256/320 kbps, FLAC,
  Opus, OGG, HLS) — все 404. Список точек монтирования Icecast закрыт паролем.

Региональные эфиры из `regions.json` нам не нужны: только Москва.

### Нерабочие и служебные
- `silver.ru/radio/48.m3u` → внутри `silver128.mp3`. Имя не врёт, а застыло: это адрес,
  зашитый в виндовый `Radio.exe` 2016 года, и станция переставляла его содержимое,
  не трогая клиентов. Не служебный мусор, а наш аварийный путь — см. ниже.
- `silver.ru/radio/128.m3u` → `http://213.59.4.27:8000/silver128.mp3` → 301 на поток № 2.
- `silverrain.hostingradio.ru/silver.m3u` → `main.hostingradio.ru/silver`: **404, мёртвый**.
- Не существуют (404): `silver32/96/128/192/256/320.aac`, `silver64/96/192/256/320.mp3`,
  `.ogg`, `.flac`, `.pls`, HLS (`.m3u8`).
- Потоков выше 128 kbps и без потерь у станции нет.

### Как хранится
`Resources/streams.json`, встроен в приложение:

```json
[
  { "id": "aac96",  "title": "Высокое · AAC 96",  "url": "https://silverrain.hostingradio.ru/silver64.aac",  "default": true },
  { "id": "mp3128", "title": "Стандарт · MP3 128", "url": "https://silverrain.hostingradio.ru/silver128.mp3" },
  { "id": "aac48",  "title": "Эконом · AAC 48",   "url": "https://silverrain.hostingradio.ru/silver48.aac" }
]
```

Плюс «Свой адрес…» в настройках: на случай, если станция сменит адреса.

### Аварийный путь

Разобрано 17.10.2026 по самому приложению станции. `Radio.exe` (23.12.2016, Delphi,
звук через `bass.dll`) **не хранит адрес потока**: в нём зашит один плейлист
`http://silver.ru/radio/48.m3u`, и это единственный адрес потока во всём бинарнике.
Реестр `HKCU\Software\Silver Rain\Radio` держит только размер окна, громкость и
скин — переназначить поток пользователь не может. Играет через `BASS_StreamCreateURL`:
ни авторизации, ни токена, ни своего протокола, так что `AVPlayer` сделает то же самое.

Отсюда то, чего не дают наши три адреса:

```
silver64.aac   ┐
silver128.mp3  ├─ все три на silverrain.hostingradio.ru — умрут одновременно
silver48.aac   ┘
48.m3u         ── на silver.ru, другой хост
```

Плейлист — **единственный указатель не на вещательном хосте**, и он это доказал:
девятилетняя программа играет до сих пор.

Поэтому: если адрес из `streams.json` перестал отвечать, прежде чем сдаваться —
разобрать `http://silver.ru/radio/48.m3u` и играть то, на что он укажет. Сегодня это
MP3 128, хуже нашего значения по умолчанию, но выбор в аварии стоит между играющим
MP3 и тишиной. AAC-плейлиста у станции нет (`silver.m3u` отдаёт 404), лучшего
аварийного пути не существует.

**Основным путём это не делать.** Официальный клиент прибит к MP3 128 навсегда,
а у того срез около 16 кГц (раздел 3). Идти за ним — осознанно ухудшить звук.

## 4. Этапы

### Этап 1 — MVP (версия 1.0)
1. Значок облака в панели меню с индикацией состояния.
2. Стеклянная панель: плашка «Сейчас играет», ползунок громкости,
   выбор качества, кнопка настроек.
3. Воспроизведение потока на Mac с автоматическим переподключением.
4. Звук идёт в системный выход Mac — на встроенные динамики или туда, куда
   выведен звук системы, в том числе на колонки по Bluetooth. Своего выбора
   устройства у приложения нет: его задаёт сама macOS.
5. Окно настроек: автозагрузка и выбор потока.
6. Интеграция с системой: плитка «Сейчас исполняется» в Пункте управления,
   медиаклавиши, экран блокировки.

### Этап 2
7. AirPlay: кнопка выбора маршрута в панели и запрет сна Mac на время трансляции
   (разделы 8.2 и 8.3). Отложено 16.10.2026, см. журнал решений.
8. Плавающий виджет поверх окон (аналог виндового) в том же стеклянном стиле.

Своей кнопки в Пункте управления не делаем — см. журнал решений 16.10.2026.
Присутствие там даёт плитка «Сейчас исполняется» из этапа 1 (§8.1), а слова
«в стиле Пункта управления» в этом плане всюду означают оформление (§6.2),
а не расширение.

### Этап 3 (по желанию)
9. Прямое управление Sonos: колонка сама тянет поток, Mac можно выключить.
10. Название текущей песни (если станция начнёт отдавать ICY-метаданные,
    или через API сайта silver.ru). **Не через файлы виндового приложения** —
    проверено 17.10.2026: `www2.silver.ru/radio/Programs.txt` отдаёт 404,
    `Black.txt` пуст, `version.txt` заморожен на «1.0». Побочная инфраструктура
    того приложения не живёт; искать надо в другом месте.

## 5. Поведение

| Ситуация | Что происходит |
|---|---|
| Запуск | Значок появляется в панели. Если включено «Включать радио при запуске» (по умолчанию — да), сразу ▶︎ |
| Клик по значку | Открывается стеклянная панель. Повторный клик или клик мимо закрывает её |
| ▶︎ | Состояние «Подключение»: значок пульсирует, затем «Играет» |
| ⏸ | Полная остановка. Следующий ▶︎ даёт живой эфир, а не место, где остановились |
| Пропал интернет | «Переподключение…», повторы через 2, 5, 10, 30, 30… с, без ограничения числа попыток |
| Сеть вернулась | Мгновенная попытка подключения (`NWPathMonitor`), не дожидаясь таймера |
| Сон Mac | Плеер останавливается, запоминаем «играло» |
| Пробуждение | Если до сна играло, подключаемся заново |
| Смена качества | На лету: новый `AVPlayerItem`, пауза меньше 1–2 с |
| Неверный «Свой адрес» | Ошибка «Не удалось подключиться» в плашке, приложение не падает |
| Громкость | Громкость приложения (`AVPlayer.volume`), системную не трогает. Запоминается |
| F8 / плитка Пункта управления / AirPods | Play/Pause |
| AirPlay выбран | Звук радио идёт на колонку, звуки системы и других программ остаются на Mac |
| AirPlay-колонка пропала | Звук возвращается на Mac (поведение системы), в плашке подсказка |
| «Выйти» | Остановка, сохранение настроек, выход |

### Состояния плеера

```
            play()                 готов               ошибка сети/потока
  idle ─────────────▶ connecting ─────────▶ playing ─────────────────▶ reconnecting
   ▲                     │                    │ ▲                          │
   │ stop()              │ ошибка             │ │  успешно                 │
   └─────────────────────┴──────▶ error ◀─────┘ └──────────────────────────┘
                                   (неустранимо: неверный URL, 404)
```

Интерфейс и значок строятся только от этого состояния, одного источника правды.

## 6. Интерфейс

### 6.1 Значок в панели меню
- **Системное облако `cloud.fill`** из SF Symbols, 14,3 pt. Силуэт логотипа станции
  был утверждён на макете, но на живой строке меню 17.10.2026 не понравился —
  см. журнал решений. Логотип остался в панели и на обложке (6.5).
- Состояния:
  - `idle`: облако нейтральным системным цветом — само подстроится под светлую
    и тёмную тему;
  - `connecting` / `reconnecting`: мягкая пульсация прозрачности;
  - `playing`: облако залито коралловым `#FF6A3D` — светлее фирменного `#FF3600` —
    в белой обводке 1 pt;
  - `error`: облако с маленьким восклицательным знаком.
- Утверждено 16.10.2026 на макете. Закрывает открытый вопрос № 1.

### 6.2 Стеклянная панель
Ширина около 300 pt, стиль Пункта управления macOS 26 (Liquid Glass).

**Эталон внешнего вида — макет:** <https://claude.ai/artifact/N1bEvpf1btHxSJhZcnvBQ5>
Три артборда: «1.0 светлая», «2.0 с AirPlay», «1.0 тёмная». Разобраны и утверждены
16.10.2026. При расхождении кода с макетом прав макет.

```
       версия 1.0 (по умолчанию)              версия 2.0, добавляется AirPlay

╭──────────────────────────────────╮      ╭──────────────────────────────────╮
│ ▣  Серебряный Дождь         ⏸   │      │ ▣  Серебряный Дождь         ⏸   │
│    В эфире · AAC 96              │      │    В эфире · AAC 96              │
╰──────────────────────────────────╯      ╰──────────────────────────────────╯
╭──────────────────────────────────╮      ╭──────────────────────────────────╮
│ Звук                             │      │ Звук                             │
│ ╭──────────────────────────────╮ │      │ ╭────────────────────────╮  ╭──╮ │
│ │🔈███████████████             │ │      │ │🔈████████████          │  │◉ │ │
│ ╰──────────────────────────────╯ │      │ ╰────────────────────────╯  ╰──╯ │
╰──────────────────────────────────╯      ╰──────────────────────────────────╯
            ( Свернуть )                              ( Свернуть )
```

Появление AirPlay укорачивает капсулу и **не двигает больше ничего**: высота плашек,
ширина панели и положение остальных блоков те же. Место под кнопку решено заранее,
возвращаться к раскладке на этапе 2 не придётся.

- Каждый блок — отдельная плашка со скруглением 20, группа объединена через
  `GlassEffectContainer`. Из чего плашка — выбирается в настройках («Материал панели»):
  четыре вида Liquid Glass и четыре материала. По умолчанию — «Материал ультратонкий»,
  см. журнал решений.
- **Цвет плашек не задаём никогда.** Стекло берёт цвет обоев за собой и режим системы;
  над водой синеет, над снегом сереет. Любая зашитая краска сделает панель чужой на
  других обоях — попытка попасть в один конкретный снимок даёт менее родной вид, а не
  более. То же про глифы: все значки из **SF Symbols**, не перерисованные.
- **Плашка «Сейчас играет»**: обложка — логотип станции на полупрозрачной светлой
  подложке (скругление 11). Подложка нужна не для красоты: без неё тёмно-синяя часть
  знака тонет в тёмной теме.
- **Ползунок громкости** — своя SwiftUI-компонента:
  - **толстая капсула высотой около 28 pt во всю ширину плашки**, значок динамика
    внутри капсулы слева, заполненная часть светлая;
  - **это осознанное отступление от Пункта управления**, где дорожка тонкая, а значки
    вынесены наружу. Причина: мишень 300 × 28 вместо 260 × 10 — втрое выше. Приложением
    управляют головой, а громкость трогают чаще всего остального. Не «чинить» обратно
    к эталону без разговора;
  - перетаскивание, клик в точку, колёсико и тачпад;
  - клик по значку динамика — без звука, повторный возвращает громкость;
  - доступность: `accessibilityValue` в процентах, стрелки на клавиатуре.
- **AirPlay** (этап 2) — `AVRoutePickerView`, обёрнутый в `NSViewRepresentable` и
  привязанный к нашему `AVPlayer`. Место — **правый край строки громкости**, там же,
  где системная кнопка вывода звука в блоке «Звук» Пункта управления. В 1.0 её нет.
  Прячется ли системная кнопка сама, когда транслировать некуда, — не проверено.
- **Качество** — `Menu` со списком из `streams.json`. Строка **по умолчанию скрыта**
  и включается настройкой (6.3). Битрейт переключают раз в полгода, а строка занимает
  место всегда; выбор потока в любом случае живёт в настройках, так что переключатель
  прячет ярлык, а не возможность.
- **Низ панели** — маленькая пилюля со словом **«Свернуть»**, по образцу пилюли
  «Изменить настройки» в Пункте управления. Словом, а не шевроном: шеврон приходится
  угадывать, а слово — нет, и мишень у слова шире.
- **Настроек и выхода в панели нет** — они в меню по правому клику на значке (6.6).
- Светлая и тёмная темы подхватываются системой.

### 6.3 Окно настроек
Стандартное окно `Settings`, одна вкладка.

**Выглядит как Системные настройки macOS, а не как своя форма.** Это не вопрос
вкуса: пользователь уже знает, как устроены настройки в системе, и наше окно не
должно заставлять его учиться заново. Способ ровно один — `Form` со стилем
`.formStyle(.grouped)` внутри сцены `Settings`. Он сам даёт сгруппированные строки
в скруглённых карточках, подпись слева, управляющий элемент справа, системные
отступы. Выравнивание руками не правим. Ширину задаём одну — 480 pt: у
сгруппированной формы своей ширины нет, а по HIG окно настроек принимает размер
вкладки и не растягивается (см. журнал решений).

Две части — **«Основные»** и **«О программе»** — переключаются сегментным
переключателем вверху окна, только словами (журнал решений).

| Элемент | Тип | Хранение |
|---|---|---|
| Запускать при входе в систему | `Toggle` | системой (`SMAppService`), не в UserDefaults |
| Поток | `Picker`: 3 потока + «Свой адрес…» | `@AppStorage("streamId")` |
| Свой адрес | `TextField` + кнопка «Проверить» (виден только при «Свой адрес…») | `@AppStorage("customURL")` |
| Показывать качество в панели | `Toggle`, по умолчанию **выключен** | `@AppStorage("showQuality")` |
| Материал панели | `Picker`: 8 системных вариантов, по умолчанию «Материал ультратонкий» | `@AppStorage("panelSurface")` |
| Плавно включать звук, когда радио включается само | `Toggle`, по умолчанию **выключен** | `@AppStorage("fadeInOnLaunch")` |
| Версия | текст | из `Info.plist` |

«Проверить» делает короткий запрос к адресу и показывает кодек, битрейт
(`icy-br`) или ошибку.

### 6.4 Плавающий виджет (этап 2)
- `NSPanel`: `.nonactivatingPanel`, `level = .floating`, без заголовка, перетаскивается за фон.
- Та же раскладка, что у панели, только компактнее.
- Включается и выключается в меню панели, положение запоминается.

### 6.5 Логотип станции
- Источник — официальный вектор с сайта станции,
  `https://silver.ru/local/templates/silver/images/icons/logo-tabbar.svg`
  (276 × 270, три фирменных цвета: `#00249D`, `#FF3600`, `#0750FF`). Проверен: ни
  скриптов, ни внешних ссылок внутри. Значок в строке меню из него больше не
  строится: там системное облако (6.1).
- **Файл лежит в репозитории** (`Assets.xcassets`, `StationLogo`). Репозиторий
  публичный, а знак — товарный знак станции; решено 17.10.2026: правообладатель
  не будет против. Из этого же файла рисуются плитка в панели и обложка.

### 6.6 Меню по правому клику
Левый клик по значку открывает панель, правый — короткое меню: **«Настройки…»**
и **«Выйти»**.

**Почему так.** Настройки и выход — редкие действия, и в панели они занимали бы
место постоянно ради пары нажатий в год. Под правым кликом панель остаётся
чистой: три блока, ничего лишнего, не во что промахнуться. Причина — удобство
повседневной работы, а не экономия места.

**Оговорка, записанная сознательно.** Правый клик — самый дорогой жест для управления
головой, а за ним спрятан единственный путь к настройкам и выходу. Решение принято
16.10.2026 с открытыми глазами; если в работе окажется неудобно, вернуть «Настройки…»
в низ панели рядом с «Свернуть» — одна строка.

## 8. Интеграция с системой

### 8.1 Now Playing
- `MPNowPlayingInfoCenter.default().nowPlayingInfo`: название «Серебряный Дождь»,
  подзаголовок «В эфире · AAC 96», обложка — логотип, `MPNowPlayingInfoPropertyIsLiveStream = true`.
- `playbackState`: `.playing` / `.paused` / `.stopped`.
- `MPRemoteCommandCenter`: `play`, `pause`, `togglePlayPause`, `stop`.
  Перемотка и «следующий трек» отключены.
- Результат: плитка в Пункте управления, медиаклавиши, экран блокировки,
  кнопки на AirPods.

### 8.2 AirPlay
- `AVRoutePickerView.player = radioPlayer.avPlayer`: маршрут только для нашего плеера.
- Качество: поток (AAC/MP3) декодируется на Mac и уходит по AirPlay 2 в **ALAC
  без потерь** (16 бит / 44,1 кГц). Потолок качества задаёт только сам поток.
- Задержка старта около 2 с, для радио это нормально.
- Громкость двух уровней: наш ползунок и громкость колонки.

### 8.3 Не засыпать при AirPlay
- Пока `playing` и маршрут внешний: `ProcessInfo.processInfo.beginActivity(options: [.idleSystemSleepDisabled], reason: "AirPlay")`.
- Экран гаснуть может, система не засыпает.
- При остановке или возврате на встроенные динамики активность снимается.
- Маршрут определяется через `AVRouteDetector` или `isExternalPlaybackActive`;
  точный механизм для macOS проверить на этапе прототипа.

### 8.4 Автозагрузка
- `SMAppService.mainApp.register()` / `unregister()`.
- Переключатель показывает реальный `status`. Если пользователь выключил
  автозагрузку в Системных настройках, переключатель это отражает.
- Статус `.requiresApproval`: подсказка «Разрешите в Системных настройках → Объекты входа»
  и кнопка `SMAppService.openSystemSettingsLoginItems()`.

## 9. Sonos (справочно, этап 3)

Найдено в `C:\Users\umkas\AppData\Local\SonosRadio\silver-sonos.vbs` (ярлык Silver Rain):

| Колонка | IP | UUID |
|---|---|---|
| A (координатор) | 192.168.1.103 | `RINCON_74CA60A7FEDE01400` |
| B | 192.168.1.137 | `RINCON_74CA60A7FC3801400` |

Как работает скрипт:
1. B присоединяется к группе A (`SetAVTransportURI` = `x-rincon:<uuid A>`).
2. Громкость обеих колонок 0.
3. На A ставится `x-rincon-mp3radio://silverrain.hostingradio.ru/silver64.aac`
   с метаданными DIDL-Lite (`object.item.audioItem.audioBroadcast`, заголовок «Серебряный Дождь»), затем `Play`.
4. Громкость плавно поднимается до 8, по шагу раз в 4 с.
5. Если A недоступна, координатором становится B.

Протокол: UPnP SOAP на порт 1400, сервисы `AVTransport:1` и `RenderingControl:1`.
Его же портируем в Swift (`URLSession`), обнаружение колонок — через Bonjour
`_sonos._tcp` или SSDP. IP-адреса не хардкодим, но держим их как запасной вариант.

AirPlay 2 работает не на всех Sonos (см. открытый вопрос № 5).

## 11. Сборка и доставка на Mac

1. Репозиторий `SilverRainMini` (приватный на GitHub, см. открытый вопрос № 4).
2. На Mac: `git clone`, затем `brew install xcodegen`, затем `make app`.
3. Подпись ad-hoc (`CODE_SIGN_IDENTITY = "-"`): платный аккаунт Apple не нужен.
4. Первый запуск: macOS спросит подтверждение (Системные настройки → Конфиденциальность
   и безопасность → «Всё равно открыть»). Один раз.
5. Готовое приложение копируется в `/Applications`, иначе автозагрузка ведёт себя нестабильно.
6. Обновление: `git pull && make app`, затем снова скопировать в `/Applications`.

### Цикл разработки
Всё на одном Mac: сборка, запуск, снимки экрана и логи
(`log stream --predicate 'subsystem == "local.oleg.SilverRainMini"'`) делаются на месте.
Логирование через `os.Logger` с этим subsystem.

## 13. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Станция в финансовых трудностях, адреса потоков сменятся | средняя | «Свой адрес» в настройках, `streams.json` легко обновить |

| `AVPlayer` нестабилен на ICY-потоке (обрывы, долгий старт) | низкая | переподключение; в крайнем случае `AVAudioEngine` + свой ICY-ридер |
| Определение «маршрут = AirPlay» на macOS неочевидно | средняя | прототип на этапе 1, запасной вариант через CoreAudio (default output device) |
| Старые Sonos без AirPlay 2 | зависит от моделей | группировка в приложении Sonos или этап 3 |
| Gatekeeper ругается после каждой пересборки | низкая | ad-hoc подпись с постоянным Bundle ID, при необходимости `xattr -dr com.apple.quarantine` |
